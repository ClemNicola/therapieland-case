# CLAUDE.md

## Project context

A patient management app used by several practitioners in a healthcare setting. It handles patient
data (PHI), so security and privacy are non-negotiable. Priorities: **minimal scope, as few files and
layers as possible, production-level security, privacy and tests.**

- `api/`: Django 6.1 + DRF + drf-spectacular, PostgreSQL 18, Python 3.14, uv
- `app/`: Vite + React 19 (React Compiler) + TypeScript + Tailwind 4 (mobile first) + TanStack Query + Zod + Orval
- `docker-compose.yml`: db, api, app for local development

The developer comes from NestJS/Java and is new to Python and Django. When they use NestJS terms,
translate them to the idiomatic Django/DRF equivalent, follow Django conventions (never NestJS
structure), and briefly explain the mapping when it isn't obvious.

## Scope

Current state: bare scaffold (health endpoint, OpenAPI, test runners). No models yet.

Planned, one step at a time (don't anticipate future steps; build only what the current step asks for):
1. Patient data model (FHIR-compliant patient data)
2. RESTful CRUD on patients
3. Simple authentication and authorization (several practitioners)
4. Search and filtering, done **client side**

## NestJS → Django/DRF mapping

| NestJS | Django / DRF |
|--------|--------------|
| Module | Django *app* (`python manage.py startapp patients`): a package with `models.py`, `serializers.py`, `views.py`, `urls.py`, `tests/` |
| `AppModule` + `main.ts` | Django *project* `config/` (`settings.py`, root `urls.py`, `wsgi.py`) |
| Controller | View / `ViewSet` (`views.py`), wired with a DRF `Router` in `urls.py` |
| DTO + class-validator | `Serializer` / `ModelSerializer` (validation + (de)serialization in one) |
| Entity + TypeORM repository | `Model` + its manager (`Patient.objects`) |
| Service | No dedicated layer by default: logic lives in models/serializers/views. Add a plain `services.py` function only when logic is shared or non-trivial |
| Guard | DRF permission class (`permission_classes`) |
| Interceptor / middleware | Django middleware |
| Pipe | Serializer field validation (`validate_<field>`) |
| Migrations (TypeORM) | `makemigrations` (autogenerated from models) + `migrate` |
| `@nestjs/swagger` | drf-spectacular (`@extend_schema` when inference isn't enough) |
| Jest + supertest | pytest + pytest-django (`client` fixture) |

## Conventions

### Backend
- Follow Django conventions. One Django app per domain (e.g. `patients/`). Keep `config/` for project-level wiring only.
- Settings come only from environment variables, with secure defaults (`DEBUG` off, no fallback for secrets).
- Deny by default: DRF's default permission is `IsAuthenticated`. A public endpoint needs an explicit
  `AllowAny` **and** an entry in `PUBLIC_ENDPOINTS` in `api/tests/test_security.py`.
- Never log, or return in errors, patient data or internal details (exceptions, hosts, SQL).
- Every API change: run `make schema`, then commit `api/openapi.yaml` (a test enforces it).
  Use explicit `operation_id`s in `@extend_schema`: they become the frontend hook names (`getHealth` → `useGetHealth`).
- Tests use pytest function style with plain `assert`, against the real Postgres test database.
- Lint and format with Ruff (`make lint`, `make format`).

### Frontend
- **Never hand-write API types, fetch calls or routes.** Use the Orval-generated hooks and types from
  `src/api/generated/` (gitignored, regenerated from `api/openapi.yaml`).
- Use Zod for client-side validation, preferring the Orval-generated schemas (`endpoints.zod.ts`).
- Tailwind only, mobile first: base classes target small screens; add `md:`/`lg:` for larger ones.
- Don't add `useMemo`/`useCallback`/`memo` by hand: the React Compiler handles memoization.
- Tests use Vitest + Testing Library: query by role or text, and stub `fetch` at the boundary.

### General
- Keep it simple: no new layers, folders or dependencies without a clear need.
- Dependencies: `make uv cmd="add <pkg>"` (api), `make npm cmd="install <pkg>"` (app), then `make up` to rebuild.
- Before considering work done, run `make test`, `make lint` and `make typecheck`.

## Commands

Run from the repo root. The stack must be up (`make up`). `make help` lists everything.

```sh
make up / down / reset / logs   # stack lifecycle (reset also deletes the DB volume)
make test                       # test-api (pytest) + test-app (vitest)
make lint / format / typecheck
make schema                     # export openapi.yaml + regenerate Orval client
make migrate / makemigrations / shell / check-deploy
make manage cmd="…"             # any manage.py command
make uv cmd="…"   make npm cmd="…"
```

URLs: app http://localhost:5173 · API http://localhost:8000/api/ · Swagger http://localhost:8000/api/docs/
