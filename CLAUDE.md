# CLAUDE.md

## Project context

A patient management app used by several practitioners in a healthcare setting. It stores health
data, so security and privacy are non-negotiable. Priorities: **minimal scope, as few files and
layers as possible, production-level security, privacy and tests.**

- `api/`: Django + DRF backend. **Backend rules (architecture, security, FHIR, TDD) live in
  [`api/AGENTS.md`](api/AGENTS.md).**
- `app/`: Vite + React 19 (React Compiler) + TypeScript + Tailwind 4 + TanStack Query + Zod + Orval
- `docker-compose.yml`: db (PostgreSQL 18), api, app for local development

The developer comes from NestJS/Java and is new to Python and Django. When they use NestJS terms,
translate them to the idiomatic Django/DRF equivalent, follow Django conventions (never NestJS
structure), and briefly explain the mapping when it isn't obvious.

## Scope

Planned, one step at a time. Build only what the current step asks for; don't anticipate later ones.
1. Patient data model (FHIR-compliant patient data)
2. RESTful CRUD on patients
3. Simple authentication and authorization (several practitioners)
4. Search and filtering, done **client side**

## API contract (backend ↔ frontend)

- `api/openapi.yaml` (generated by Django, committed) is the single source of truth for types and routes.
- Orval generates TanStack Query hooks, types and Zod schemas from it into `app/src/api/generated/`
  (gitignored, regenerated before `dev`, `build`, `test` and `typecheck`).
- After any API change: `make schema`.
- The Vite dev server proxies `/api` to Django: one origin, so no CORS.
- Auth is a session cookie (HttpOnly). Before any unsafe request, the frontend calls `GET /api/auth/csrf/`
  once and sends the `csrftoken` cookie value as the `X-CSRFToken` header. `401` means "log in again".
- Patients are FHIR R4 resources (`/api/patients/`): list = FHIR `Bundle`, errors = FHIR
  `OperationOutcome` (show `issue[].diagnostics`, map `issue[].expression` to form fields).
- Local demo accounts and patients (seeded by `make up`): see the README.

## Frontend conventions

- **Never hand-write API types, fetch calls or routes.** Use the generated hooks and types.
- Use Zod for client-side validation, preferring the generated schemas (`endpoints.zod.ts`).
- Tailwind only, mobile first: base classes target small screens; add `md:`/`lg:` for larger ones.
- Don't add `useMemo`/`useCallback`/`memo` by hand: the React Compiler handles memoization.
- Tests use Vitest + Testing Library: query by role or text, and stub `fetch` at the boundary.

## General

- Keep it simple: no new layers, folders or dependencies without a clear need.
- Dependencies: `make uv cmd="add <pkg>"` (api), `make npm cmd="install <pkg>"` (app), then `make up` to rebuild.
- Before considering work done, run `make test`, `make lint` and `make typecheck`.

## Commands

Run from the repo root. Everything runs in the containers, so the stack must be up. `make help` lists all targets.

```sh
make up / down / reset / logs   # stack lifecycle (reset also deletes the DB volume)
make test                       # test-api (pytest) + test-app (vitest)
make lint / format / typecheck
make schema                     # export openapi.yaml + regenerate the Orval client
```

URLs: app http://localhost:5173 · API http://localhost:8000/api/ · Swagger http://localhost:8000/api/docs/
